# Signature removal

`--remove-signature` removes the signature from the selected executable and
purges the selected bundle's signature directory. Mach-O signatures use executable
replacement; [generic signatures](generic-removal.md) use attribute removal in
place. It does not construct or
validate a resource envelope. Resources, nested code and unselected framework
versions do not need to be readable. `--deep` does not make removal recursive.
This policy is shared by Linux, macOS and Windows.

## Operation and failure boundaries

The bundle loader selects the layout and framework version. Removal validates
that selection, reads the selected executable and checks its platform metadata,
then prepares and commits its unsigned replacement through APFS `hostdata`.
Signature-directory cleanup follows executable commit. The existing rooted
identity, regular-file, cancellation and cleanup-order checks remain in place.

An unreadable resource or child cannot block removal. Unrelated root entries,
malformed child metadata, resource symlinks and hard links to executable or
envelope data do not require traversal. Replacement and unlinking preserve the
other hard-link names and their bytes. Removal does not follow resource links.
Signing and verification retain their own resource/layout validation.

An unreadable **selected executable** still fails. Denied executable metadata
reads also fail before replacement or cleanup. Permission diagnostics use the
native `Permission denied` / `Operation not permitted` wording, while the public
API retains the original cause for `errors.Is`. Existing post-commit cleanup
failures preserve their nontransactional boundary and cancellation behavior.

## Evidence and tests

The pinned Apple `SecCodeSigner::Signer::remove` body dispatches directly to a
Mach-O editor or the representation's writer; it does not call the signing
resource builder. Complete removal/controller and writer bodies are already in
[`apple-writer.json`](../spec/apple-writer.json), generated by
[`extract-writer.go`](../scripts/extract-writer.go) with Clang on both SDK targets.
This phase regenerates that evidence unchanged. Source review of
`BundleDiskRep::setup` establishes that executable platform metadata queries
belong to bundle construction; native tests qualify the current host behavior.

[`removal_resources_test.go`](../acceptance/removal_resources_test.go) adds 27
portable cases: ten effective resource/child/version read denials, four selected
executable denials with API error-identity assertions, five unrelated layout
members, and eight malformed-child/symlink/hard-link cases with and without
`--deep`. Each denial is proved effective before invoking the CLI.

[`removal_resources_darwin_test.go`](../acceptance/removal_resources_darwin_test.go)
adds 50 native resource-permission comparisons across ten locations and five
rights, plus 16 selected-executable read/read-EA failures. Including the thirteen
portable layout/alias cases, 79 cases compare with native codesign. Assertions
retain complete operand bytes, output/status, inode effects and ACL observations.
Where a denial also prevents observing the ACL, its exact observation error is
recorded; it is not represented as an empty ACL. Restrictions are lifted only
after the operation and ACL observation, to inspect the resulting bytes.

Every foreign producer exports ten complete removal archives. The existing
`TestVerifyImportedRemoval` job now requires all twenty Linux/Windows archives
and compares them with independent Apple removal results. Existing artifact
counts, native regression matrices, race/fuzz, lint, GoReleaser and coverage
**above 95% in every production package** remain mandatory.

## Remaining work

This profile does not complete removal or filesystem parity:

- Native bundle discovery can fall back to Info.plist when the executable cannot
  be selected under read-attribute or read-security denial. Probes show native
  removal then preserves the executable, removes `com.apple.cs.*` signature
  attributes from Info.plist and purges the envelope. Go still reports discovery
  failure. The generic attribute-removal protocol now exists on all hosts;
  integrate this fallback without treating arbitrary read failures as success.
- Denied metadata reads on entries **inside the signature directory** remain a
  gap. Native enumeration can use directory-entry types without the eager stat
  calls performed by Go's rooted directory reader. A shared filesystem primitive
  belongs in APFS, preserving containment, type checks, bounds and cleanup order.
- Destination ACL inheritance and deny-delete temporary-file names, contents and
  cleanup need allocation-level qualification and shared SDK work. This phase
  does not change that writer contract.
- Generic signing/verification/display, detached signatures, additional filesystem and
  authorization contexts, concurrent mutation and large streamed inputs remain
  in the [implementation plan](implementation_plan.md).

Reproduce the wider discovery/inheritance observations with
`go run scripts/probe-signing-security.go -candidate /path/to/macoscodesign`.

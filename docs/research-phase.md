# Whole-roadmap research and evidence harness

This phase prepares the larger implementation phases without changing production
signing policy. The [research map](../spec/research-roadmap.json) assigns all 88
inventory entries to their implementing phase, links their current native
applicability observations, specifies 39 future native case families and records
the original 12 prerequisite decisions. The [Phase 02 filesystem finding](portable-io-lifecycle.md)
adds a separately tracked thirteenth prerequisite. Future case specifications are explicitly unexecuted;
they are not expected results generated by the Go implementation.

## What the research establishes

[Eleven complete Apple bodies](../spec/apple-prerequisites.json) now have Clang
AST evidence for arm64 and x86_64 Darwin targets. The extractor preserves source,
SDK-header, driver, body and translation-unit hashes. Private interfaces are
identified declaration shims; they are not implementations of Apple services.
The pinned source revision can differ from the installed macOS 27 binary.

The new bodies cover dynamic identity/status/validation, remote signing setup and
CMS dispatch, detached signature destinations, ticket extraction/registration and
notarization lookup. They establish these prerequisites:

| Area | Finding | What still needs implementation or access |
| --- | --- | --- |
| Live process/hosting | Apple validates the host chain, reads host/kernel state and compares the running CDHash with disk | A permitted way to obtain actual target state; static verification or a snapshot cannot establish equivalent live behavior |
| Detached database | Native detached output can enter `SignatureDatabaseWriter`; the reviewed implementation uses SQLite at `/private/var/db/DetachedSignatures` | Schema/transaction work plus isolated real-store authorization and observable registration |
| Remote signing | A signing callback receives digest/algorithm context and supplies signature bytes for CMS | The current CLI provider-selection contract and actual authorized provider; this source does not define a network protocol |
| Notarization | Published bodies delegate to SecAssessment, distinguishing ordinary lookup and forced-online revocation checks | Authenticated ticket/protocol/trust evidence and current cache/freshness/error policy |
| Keychain/hardware | Existing test identities and `crypto.Signer` provide useful controls, not arbitrary protected-key access | Real authorized stores/devices and a permitted portable access implementation |
| Dylib/allocator overrides | Arbitrary native-library/helper execution conflicts with the production boundary | An explicit resolution of that conflict; built-in signing/allocation does not implement arbitrary overrides |
| Hybrid/constraints | Parser/SDK recognition does not establish modern private algorithms or complete schemas | Legitimate native hybrid fixtures/providers and full versioned constraint/slot corpora |

A [Clang-built SDK oracle](../scripts/oracles/process-context.c) holds only its own
disposable child process alive. Five API controls establish that its self, host,
static representation, dynamic information and validity are accessible. Six
independent native CLI cases compare live verification/hosting with a static path
and an explicitly relative numeric filename. [Raw observations](../testdata/research/process-context.json)
retain PID/path, status, stdout/stderr and provenance. Repeat checks permit only the
declared fixture PID/directory substitutions; all other output and exits must match.
No user keychain, trust-store mutation or external signing credential is involved.

This capture ran on macOS 27.0.1 build 26A434, arm64. Its `codesign` hash matches
the inventory's macOS 27.0 reference. The new OS/build is recorded rather than
silently relabeling the old baseline. Neither the SDK control nor cross-target
AST compilation proves a non-Darwin kernel-state implementation.

## Reference and APFS decisions

The map records exact URLs/hashes for the Apple prerequisite source review and
selected pinned Rust/Go reference files. apple-platform-rs's remote signer has its
own WebSocket protocol; its macOS keychain module uses Security framework bindings.
Neither is a drop-in solution for Apple's remote CLI semantics or this project's
no-native-binding constraint. Its YubiKey implementation reinforces the separation
between file-format support and access to a real device. Relic's CMS separation is
useful design input; its certificate dependencies still require this project's
guard review. These references were inspected, not executed or copied.

The APFS audit uses the downloaded module pinned in `go.mod`, not the neighboring
working tree. Phase 02 currently pins merged main commit `8821862a12de` through
`v0.17.3-0.20261005072906-8821862a12de` under the upstream release batching policy.
It records module sum, API file hashes and concrete reuse decisions:
rooted replacement/restore/close, existing ACL staging, the DMG footer and streaming
image reconstruction. Codesign still needs lifecycle integration and broader native
image/name matrices. A source inventory does not justify a speculative SDK rewrite;
open an upstream prerequisite only when a captured case needs a missing public API.
Phase 02 updates the original v0.17.0 audit to the published v0.17.1 prerequisite
and includes both fallback implementation files. The v0.17.2 update also audits
the Windows rooted replacement and sparse backup filter. No local module replacement is used.

## Native probe refactor

The removal-plist driver is separated into grammar, Unicode, legacy, multibyte and
stateful input modules. All modules remain research-only Go files. Invoke it with
all five input files:

```sh
go run scripts/probe-removal-plist-interpretation.go scripts/probe-plist-inputs-*.go \
  -profile iso2022-extensions -out artifacts/plist-iso2022-extensions.json
```

Every corpus now records transitive source hashes, including the driver, all input
modules, module files and native value corpora actually read. Existing unit replay
checks these hashes. Module/oracle source bytes are explicitly pinned to LF so
Windows verifies the same research inputs without normalizing signed fixtures.

The [refactor audit](../testdata/research/plist-probe-refactor.json) records a fresh
native recapture of **all 8,340 cases in eleven profiles**. Every complete `cases`
object and native binary hash matched the pre-refactor record. Only provenance
changed; no expected selection, bytes, metadata or mutation result was replaced.
The dependent complete-value corpus was also freshly recaptured with `plutil`: all
1,294 inputs, statuses and complete values matched before its input hashes changed.
The CI native-capture job continues running every profile and the exhaustive value
and stream oracles. The refactor does not substitute cached answers for execution.

## Required evidence partitioning

[`ci-test-plan.json`](../spec/ci-test-plan.json) derives its initial case manifests
and scheduling weights from successful workflow
[37174795827](https://github.com/deploymenttheory/go-macos-codesign/actions/runs/37174795827),
head `708528a670126352378f7a7ffee82eed183454b1`. The manifest retains original log
hashes. It includes every nested test name and terminal status in a per-root digest,
so a removed/renamed case or newly skipped test cannot pass just because its parent
passes. Existing native-only/opt-in skips remain recorded limitations, not new skips.

| Host | Unit outcomes | Acceptance outcomes | Acceptance attestations | Exported files |
| --- | ---: | ---: | ---: | ---: |
| Linux | 43,657 | 19,893 | 18,515 | 9,724 |
| Windows | 43,663 | 19,249 | 17,871 | 9,724 |
| macOS | 43,668 | 25,237 | 23,717 | 9,724 |

Export names come from that run's dedicated `signed-*` artifacts, whose upload
included hidden files. Its general evidence artifacts omitted 81 `.DS_Store`
fixture files. The new archive transport preserves the complete 9,724-file tree,
including those existing test inputs; none are discarded to match an incomplete
download. The complete export name sets match between Linux and Windows.

These counts describe terminal test records, including parent tests and existing
skips; they are not counts of newly implemented features or unique native probes.

Each OS has one unit worker and four acceptance workers. Whole top-level tests
stay intact; no internal case matrix is sampled. Longest-first assignment uses the
maximum observed duration across hosts, producing approximately 510 seconds of
historical assigned work per acceptance shard. That is a scheduling estimate;
measure actual CI wall/worker time before claiming a speedup.

[`evidence.py`](../scripts/evidence.py) writes a completion receipt only after its
full test invocation, outcome check and coverage conversion succeed. Aggregation
requires all five parts, matching commit/run/attempt/OS/toolchain/source bytes and
instrumentation, exact receipt file hashes, complete nested outcomes and the full
attestation/export manifests. Duplicate shards, cases and exported artifacts fail.
Cancelled/failed jobs cannot pass by leaving partial artifacts behind.

Shard and complete-OS artifacts contain `evidence.tar`. The archive preserves
native case filenames byte-for-byte, including URL colons that GitHub's artifact
uploader rejects as loose files. Extraction accepts only unique regular files at
relative paths in a fresh directory; links, traversal, duplicate names and stale
destinations fail. Receipts still hash every extracted file before aggregation.
Each host extracts its own evidence; Windows rejects names that would create NTFS
alternate streams. The Linux/Windows foreign producer artifacts remain directly
readable by the native import job.

Coverage remains a within-OS union of atomic unit/CLI profiles, strictly **above
95% for every production package**, including newly added packages. Nothing is
averaged across OSes. Four package race workers preserve every current production
library/internal package, and four fuzz groups preserve all thirteen sixty-second
targets and RC2 tests. The research checker rejects missing race packages or fuzz
targets/durations. GoReleaser still builds all six production packages/archives.

The full instrumentation manifest also pins the existing local RC2/Afero replacement
packages present in baseline profiles. They remain in raw merged coverage. The
production coverage gate uses every current `pkg`, `internal` and `cmd` package,
as the monolithic harness does; dependency blocks cannot replace a missing
production package or raise its percentage.

Before Apple's unchanged import suite runs, a new gate requires exactly the Linux
and Windows producer directories, current provenance and every exported file/hash.
Existing native case-by-case import assertions remain in place. Native capture,
lint, dependency/fixture guards and release checks remain mandatory.

## Reproduction and maintenance

```sh
python3 scripts/check-research.py
python3 -m unittest discover -s scripts -p 'test_*.py'
go run scripts/extract-prerequisites.go
go run scripts/probe-process-context.go -check -out artifacts/process-context.json
```

The extractor requires the pinned Apple files in `.research/apple` and the host
SDK. Source URLs/hashes are recorded in its manifest; Clang/native tools are never
production dependencies. The process probe requires macOS and compiles its own
short-lived oracle with Clang.

For local partitioned validation, run `scripts/evidence.py shard PART --output DIR`
for `unit`, `0`, `1`, `2`, `3` into five fresh directories beneath one input directory,
then `scripts/evidence.py aggregate --inputs INPUT --output OUTPUT`. On a Mac set
`MACOSCODESIGN_REQUIRE_APPLE=1`. Run the acceptance workers serially on a single
interactive Mac: existing native chain controls temporarily manage a disposable
keychain/search list and must not race each other's cleanup. CI workers use separate
runner jobs. The original `make verify` remains the monolithic local path.

When adding tests, update manifests from reviewed full execution evidence, inspect
exact additions/removals/skips and retain raw logs. Do not regenerate expected
outcomes after a failure merely to make a smaller suite pass. The merged final CI/artifact audit reconciled the old and partitioned suites
before Phase 02 began. All 88 feature statuses remain unchanged.

and release-build gate before merge. Each OS exported 9,724 required files,
including the complete signed-artifact baseline and 81 hidden `.DS_Store` files.
Eighteen foreign attestations matched CI, local and baseline evidence.

| Measurement | Previous baseline | Final partitioned run |
| --- | ---: | ---: |
| Workflow wall time | 40m 22s | 33m 42s |
| Summed job execution | 115m 20s | 130m 18s |
| Retained artifact bytes | 381,566,752 | 560,655,889 |

This run finished about 16.5% sooner in wall time, with greater worker and artifact
cost. The macOS aggregation job also queued for approximately fourteen minutes;
these observations are not a guaranteed speedup for every future run. Final
source-hash, complete-case/status and artifact audits passed. All 88 feature
obligations still require their implementing phases.
